# Сводка по пет-проекту: Микросервисная платформа логистики и доставки

### 1. Архитектура и стек технологий

Проект представляет собой распределенную систему из 3 бизнес-микросервисов и 2 инфраструктурных компонентов. Архитектура построена на принципах слабо связанной событийной архитектуры (Event-Driven Architecture).

* **Язык:** Java 17+ / Spring Boot 3.x
* **Инфраструктура:** Spring Cloud (API Gateway, Eureka Service Discovery)
* **Базы данных:** PostgreSQL (основная БД для сущностей), Redis (распределенный кэш для быстрых данных)
* **Брокер сообщений:** Apache Kafka (асинхронное межсервисное взаимодействие)
* **Сборка и DevOps:** Maven/Gradle, Docker, Docker Compose (запуск всей системы одной командой)
* **Документация:** OpenAPI / SpringDoc Swagger (единая точка для тестирования API через Гейтвей, без сложного фронтенда)

---

### 2. Структура компонентов системы

1. **Gateway Service (Порт 8080):** Единая точка входа для всех запросов. Отвечает за маршрутизацию (роутинг) запросов к нужным сервисам и в перспективе за единую авторизацию (Spring Security + JWT).
2. **Eureka Server (Порт 8761):** Сервер регистрации, через который микросервисы автоматически находят сетевые адреса друг друга.
3. **Order Service (Первый микросервис):** Управляет пользователями и заказами. Принимает запросы на создание доставки, сохраняет данные в свою схему PostgreSQL и отправляет событие о новом заказе в Kafka.
4. **Processing / Courier Service (Второй микросервис):** Отвечает за логику складов и подбор курьеров. Слушает Kafka, забирает новые заказы, использует **Redis** для быстрого расчета и хранения динамических статусов курьеров (свободен/занят, координаты). Результат назначения отправляет обратно в Kafka.
5. **Notification Service (Третий микросервис):** Слушает Kafka и реагирует на изменения статусов заказов. Отправляет реальные письма на email (Spring Mail) и имитирует отправку SMS/Push-уведомлений через лог-заглушки (Mocks).

---

### 3. Организация кода и репозитория

* **Формат:** Монорепозиторий (все сервисы лежат в одном репозитории на GitHub в отдельных папках, что упрощает демонстрацию работодателям).
* **Docker Compose:** В корне проекта настраивается один файл `docker-compose.yml`, который поднимает локально все базы данных (Postgres, Redis), Kafka и сами микросервисы.

---

### 4. Пошаговый план разработки (План действий)

* **Шаг 1:** Разработка `order-service` как изолированного приложения. Настройка PostgreSQL, сущностей и логики заказов. Тестирование эндпоинтов напрямую через его собственный Swagger.
* **Шаг 2:** Разработка `processing-service` (курьеры и кэш Redis) также в изолированном режиме.
* **Шаг 3:** Подключение Apache Kafka для настройки асинхронного обмена сообщениями между сервисами. Разработка `notification-service`.
* **Шаг 4:** Сборка инфраструктуры Spring Cloud. Добавление `eureka-server` и настройка правил маршрутизации в `gateway-service`, чтобы перевести все запросы на единый порт 8080.
* **Шаг 5:** Написание Dockerfile для каждого сервиса и итогового `docker-compose.yml` для автоматизации запуска.
